| Optional capability | Concept and position in the workflow | Software entry point | Setup and interpretation |
| --- | --- | --- | --- |
| **Mondrian calibration** (conditional calibration) | At step 3, use defined groups in the applicable calibration construction; group information also matters at prediction/explanation time. | `calibrate(..., bins=...)` with consistent per-case `bins=` at use, **or** a stored categorizer via `mc=`. | {doc}`Group-label channels and conditions </foundations/how-to/conditional_calibration>`. Group labels are not target labels; grouping alone does not establish fairness. |
| **Guarded explanations** | During steps 5a/5b, check selected representatives of candidate conditions using calibration-derived support information. Inspect the retained rules and audit. | Pass `guarded_options=GuardedOptions()` to the explanation call; inspect `get_guarded_audit()`. | {doc}`Guard setup, supported explainer and limits </foundations/concepts/guarded_explanations>`. This does not certify every value in a condition or automatically check the original case. |
| **Conjunctions** | For explanation rules in steps 5a/5b, combine feature conditions and assess the combined rule. | `add_conjunctions(...)` on a supported explanation collection or item. | {doc}`Combined rules and supported calls </foundations/concepts/alternatives>`. Do not obtain a combined rule by simply adding individual weights, or infer causal interaction. |
| **Alternative filtering** | After step 5b, select existing alternative rules using a stated criterion on the relevant output scale. | `ensured_explanations()` and the other documented alternative-filter methods. | {doc}`Mode-specific filter criteria </foundations/concepts/alternatives>`. An ensured filter compares reported interval widths; it does not establish a beneficial intervention or improved accuracy. |
| **Rejection** and reject policy | At prediction/explanation time, compute a task-specific case status and control processing. The application determines follow-up. | `reject_policy=RejectPolicy.FLAG` tags cases; other enum members select processing. Set up the applicable rejection procedure first. | {doc}`Rejection setup, policies and return types </practitioner/advanced/reject-policy>`. This handles cases, not alternative rules, and is not a universal test of correctness or distribution shift. |

These are optional choices, not additional predictive tasks or compulsory
sequential stages. Availability and supported combinations depend on the task,
output mode, configuration and library version. Browser controls may expose a
subset of the Python library's capabilities.
